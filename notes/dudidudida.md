# dudidudida (HTB, rev)

**Flag:** `HTB{every_node_by_node_every_edge_by_edge_fadfba787feae}`

## Target
- `dudidudida.exe`: stripped PE32+ x64, written in D (druntime/phobos strings, `challenge.dudidudida.Dir`). No wine was needed because the whole solve was static.
- radare2 wrapper is broken on this box (`~/.local/bin/r2` → missing path). I used objdump + capstone instead.

## How it works
- main (`0x14003ecc0`): `readln` → `strip` → `0x140001100` turns the input into a bitstring (MSB first) → `spawn(0x14000b180, bits)` → `receiveTimeout(3s)`.
  The reply handler treats msg 1 as Failed. On msg 0 it prints Success only if every int in the 224-int table at `0x1400d9aa0` is no longer -1.
- **224 "cell" functions** form a maze (a directed graph with out-degree 3). Each cell:
  1. Fails if `table[idx] != -1` (no revisits), then sets `table[idx] = idx`.
  2. `global += BigInt("0x" ~ sha256([idx]).toHexString)`
  3. Fails if fewer than 2 bits remain. Otherwise it reads 2 bits and maps them through a global AA `Dir → "00".."11"`, then tail-calls the neighbour. A missing edge means fail.
  4. 28 cells are **checkpoints**: they first re-permute the Dir map, then require `global % M == C` (M is a 256-bit BigInt at `0x1400d9e40`, C is a decimal constant), then reset `global = 0`.
  5. One cell (195, at `0x140005de9`) sends 0 (success) on Dir 2.
- I identified the BigInt ops from the Phobos opOpAssign shapes: `0x14004ae30` passes `sign != y.sign` into addOrSub, so it is `+=`. `0x14004b200` does a div-by-zero check and then "if zero, sign=false", so it is `%=`.

## Solve
- The goal is a Hamiltonian path from cell 203 that ends with cell 195's exit. It makes 224 moves × 2 bits = 448 bits, so the input is 56 bytes and is the flag itself.
- Checkpoint sums made each segment unique. A light test with L≤18 explored 10M paths and found exactly 1 matching first segment.
- Pure DFS blew up because paths can wander a long way without reaching a checkpoint. Fixes:
  - cap the segment length (iterative deepening, SEGMAX=10 is enough)
  - Hamiltonian in/out-degree pruning
  - `HTB{` prefix and printable charset
  - written in C (`solve/solve.c`, data generated by `gen.py`)
- Checked with an independent Python simulation of the cell logic: `Success!`, 448/448 bits used.

## Lessons
- "Thread + receiveTimeout + many near-identical functions" means a graph or maze. Parse all cells automatically into JSON first.
- For path search with sparse checkpoints, **bound the length between checkpoints**. Otherwise DFS explores huge checkpoint-free wanders.
- Don't `pkill -f <name>` from a command line that contains `<name>`, because it kills its own shell.
